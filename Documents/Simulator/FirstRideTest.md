# 第一版 VR 騎行測試

更新：2026-11-01。此文件記錄可執行的第一版設計；未定的正式研究規格仍放在 [Spec.md](Spec.md)。

遊戲內選單已改為可在 VR 以控制器射線／扳機操作，並保留 JSON profile、Desktop/VR 選擇及輪組修正；最新操作請先看 [SetupAndProfiles.md](SetupAndProfiles.md)。

## 已確認條件

- Focus 3 + VIVE Business Streaming + SteamVR 已能執行 Sample Scene；先沿用 Windows PCVR。
- 暫時用 Vive controller 的搖桿與按鍵；PS4 手把是備用。後續改接專用擬真控制系統。
- 騎行輸入不依賴控制器位置、旋轉或手部追蹤；VR 選單使用控制器位姿追蹤與射線。既有「手部位置突然不靈敏」問題需在選單操作時另確認，頭部追蹤也須正常。
- 目標是普通自排速克達的騎乘視角。座椅、實車固定與場地由現場調整；軟體保留眼高、前後左右位置及朝向校正。
- 暫按總預算 NT$3,000 規劃，涵蓋素材、sensor 與其餘硬體；這是工作假設與分配目標，不是購買授權或死上限。

## 這一輪要回答的問題

1. 靜止時的車身尺寸、把手位置與視野是否合理？
2. 油門、煞車、轉向的反應是否可預期？是否需要反覆修正方向？
3. 直行加減速、寬彎、連續左右彎，哪一段開始引起不適？
4. 車身傾斜、鏡頭傾斜、周邊視野遮罩、後照鏡各自如何影響感受與效能？

這一輪只能對當前控制器、座位、串流與視覺設定做結論。專用把手加入後，必須重測操作性與暈眩，不能直接沿用 controller 的結果。

## 場景與操作

- 場景：`VR-Motor-Street-Riding/Assets/Scenes/FirstRideTest.unity`。
- Unity 選單 `AIT > Riding > Setup and Play Mode` 選 Desktop 或 VR；在騎行場景直接按 Play，預設先打開模式選擇視窗。
- 設定檔：`Assets/MotorSimulatorAssets/FirstRideGenerated/FirstRideSettings.asset`。執行時使用副本，操作面板不會把試調數值寫回素材設定。
- 初始狀態為暫停並顯示遊戲內選單；先坐好、看向車頭、釋放油門並選開始，第一次自動置中。暫停、重設與切換段落後不會自行行進。
- 使用現有 OpenXR PCVR 設定；沒有另行安裝 SteamVR Unity Plugin、HTC SDK 或更動套件版本。
- 校正、換路段、輸入、舒適選項與設定檔集中到遊戲內選單，調整立即生效。VR 以控制器射線和扳機選取，Desktop 以滑鼠操作。鍵盤騎行須讓 Game View 取得焦點。

設定快捷鍵已移除；調整與換路段都從暫停選單操作。

| 動作 | Vive Focus 3 controller | PS4 / 一般 Gamepad | 鍵盤 |
|---|---|---|---|
| 轉向 | 左搖桿左右 | 左搖桿左右 | A / D |
| 油門 | 右扳機 | R2 | W |
| 煞車 | 左扳機 | L2 | S |
| 低速倒退移車（按住；放開停下） | 右 B | ○ / East | R |
| 暫停／開選單 | 左 X | Options / Start | P / F2 |
| VR 選單選取 | 控制器射線指向，按下並放開扳機 | VR UI 使用控制器；手把僅用於騎行 | Desktop 用滑鼠 |
| 開始 | 選單「開始／繼續騎行」 | 同左 | 同左，或 P |
| 立即停止 | 按住左 Grip | 按住 L1 | Space |

上述 Vive 按鍵以 OpenXR `primaryButton` / `secondaryButton` 對應；實機尚需逐鍵核對。PS4 使用 Unity Input System 的 Gamepad 對應，先接 USB；本次自動測試不代表實體 PS4 已驗證。

## 道路與視覺條件

| 段落 | 場地 | 速度設定 | 試騎內容 |
|---|---|---|---|
| 01 | 約 280 m 平坦直道 | 遊戲內「速度」共用設定 | 放油門滑行、煞車、看儀表與左右轉頭；終點自動暫停 |
| 02 | 兩段 160 m 直道、32 m 半徑彎道的環形路 | 同上 | 入彎前減速、維持路線、回正方向 |
| 03 | 平坦、平滑過渡的 S 彎道路 | 同上 | 比較左右轉換；終點自動暫停 |

地圖固定速限看板與分段限制已移除；預設上限 40 km/h，可在 VR／Desktop 遊戲內「速度」調整並存入 profile。直角街道與其他車輛轉彎改用 [CityCorners.md](CityCorners.md) 的獨立場景。兩張既有場景也已加入固定握把雙手。

道路寬 8 m，出生點位於右側約 1.75 m，並有標線、20 m 間距路柱與遠處建物作為距離和速度參照。這是可重複的試車場，尚非台灣市區交通場景。路外超過容許走廊或接觸路柱時停止；沒有翻車、撞擊鏡頭或自動瞬移回路面。

| 視覺條件 | 車身 | 額外鏡頭 Roll |
|---|---|---|
| StableHorizon，預設 | 隨橫向加速度傾斜，上限 18° | 0° |
| UprightVehicle | 維持直立 | 0° |
| ReducedCameraLean，主動選用 | 同 StableHorizon | 車身傾角 × 0.2，上限 3° |

這些數字是初始調參值，沒有經過舒適度或實車有效性驗證。三個條件的運動模型相同。頭盔本身的六自由度追蹤保留，不對頭部姿態做平滑或用頭部朝向轉車；額外 Roll 以眼睛位置為中心，避免頭部繞車體產生額外側移。

周邊 vignette 預設關閉，可以在暫停時單獨開啟比較；之後的盲區任務必須另測其遮擋影響。左右後照鏡預設開啟，以 256 px、每鏡每秒最多 30 次更新呈現後方視野。初版鏡面是固定方向、單視點的後視攝影畫面，並非隨雙眼位置校正的真實平面反射，不適合直接量測盲區察覺能力。

音效是隨油門與速度改變的簡易合成提示，可關閉；不是實際 125 cc 引擎錄音。素材評估與替換方向見 [AssetAndBudgetOptions.md](AssetAndBudgetOptions.md)。

## 車輛模型與日後輸入

初版採平面運動學近似：速度、軸距、前輪轉角決定軌跡；高速降低最大轉角，另限制角速度與橫向加速度。煞車優先於油門，鬆油門時有滑行阻力。90 Hz 固定步長計算，顯示位置做插值。

預設軸距 1.33 m、加速度 1.8 m/s²、煞車減速度 4 m/s²、低/高速最大轉角 38°/5°、轉角變化率 55°/s。轉角與角速度上限隨車速平滑過渡，至 25 km/h 使用高速值；低/高速角速度上限 75°/s、28°/s，最大橫向加速度仍為 3 m/s²。低速轉向不再被固定 28°/s 卡住。模型未包含平衡、輪胎側滑、懸吊、質量轉移、轉向扭矩或反向操舵；禁止把這些參數當成特定實車的量測值。

迴轉建議先降到 5–8 km/h。使用專案預設、從右側車道中心 +1.75 m 起轉，5/8 km/h 的完整 180° 軌跡連同約 0.77 × 1.90 m 車體包絡，可留在 8 m 路寬內；8 km/h 亦通過實際場景 Play 檢查。10 km/h 同一起點的包絡會到道路中心外約 4.25 m，因此不能保證一次轉完。這是初步幾何驗收，非真車迴轉半徑量測。

倒退是模擬腳推移車，按住倒退鍵直接後退，不需加油門，上限 3 km/h、加速度 0.8 m/s²；放開會減速至停下。往前行駛時按倒退，先減速到零，再向後走；倒退中加油門不會直接跳成前進。煞車優先且不會自動切入倒退。倒退時轉向的軌跡方向隨速度符號反轉，輪胎倒轉，儀表顯示 R 與速度絕對值。開始騎行前需同時放開油門與倒退鍵。

VR／Desktop 選單的「操控」分頁可調低速最大轉角、低速轉向上限、倒退速度，並可套用上述低速預設。調整後到「設定檔」儲存。舊 profile 保留原轉角，例如 28°；載入後若仍轉不過來，先套用低速預設再試。

輸入邊界是 `RideInputProvider.ReadInput()`，輸出 steering [-1,1]、throttle/brake/reverse [0,1]、connected、sampleTime 與操作事件。sampleTime 是 Unity 啟動後的秒數；硬體 adapter 只在新 sensor 資料抵達時更新，不能用讀取快取的時間充當新樣本。NaN / Infinity 會拒收，逾時 0.25 秒停止。未連接 adapter 時不允許 External 模式啟動。

目前 steering 表示「要求往哪個方向轉」，不等於把手量得的扭矩或真實前輪角度。日後若取得 torque、steering angle 或 body lean，需明確選擇對應模型與控制律，再比較低速與一般車速的手感。

## 建議現場流程

1. 記錄日期、頭盔與串流版本、USB/Wi-Fi、更新率、控制方式、座位與視覺條件。正式測試前先核對單位比例、按鍵、頭部追蹤與停止鍵。
2. 靜止檢查：校正眼位，確認把手距離、低頭看儀表、左右回頭與鏡面方向；先記錄基準不適程度。
3. 先用 StableHorizon、vignette 關閉與固定鏡面設定。每段先短時間試騎，暫停後再決定是否繼續，無須完成路線才能結束。
4. 操作員記下不適出現時刻、當時動作與自訂 0–10 評分；任何不適或受試者要求皆可立即停止，不以撐完測試作目標。
5. 基準設定能接受後，每次只改一項視覺條件。在相同段落比較；若初次仍有明顯不適，不必為比較而開啟鏡頭 Roll。
6. 比較前確認已回到本人的測前狀態，記錄休息長度、測試順序與暴露時間。多人比較時交錯條件順序，避免把適應或累積不適誤認為設定效果。
7. 每段另記「速度感、煞車反應、方向可預期性、把手/眼位是否合理」與自由回饋。這些可用性評分和暈眩評分分開。

初版內建的是自訂 0–10 pilot rating，不是 SSQ 或 FMS。後續若使用標準量表，需獨立採用其原始題項、計分和施測流程。

## 紀錄與驗收

Editor 紀錄位於 `VR-Motor-Street-Riding/Personal/RideTests/<UTC時間-隨機碼>/`；此 Personal 目錄由 `.git/info/exclude` 排除。獨立 Player 紀錄在 `Application.persistentDataPath/RideTests/`。檔案不傳送至網路。

- `session.json`：初始設定 JSON、測試段落、Unity/平台/GPU、XR 回報更新率。
- 紀錄 schema 升為 `ait-first-ride-v2`；`speed_mps` 為帶正負號速度，負值表示倒退，`telemetry.csv` 尾端新增 `reverse_input`，原欄位順序保留。
- `telemetry.csv`：預設 20 Hz，速度、加速度、轉向輸入、油門、煞車、車體位置與朝向、額外傾角、相對車體的頭部姿態、道路中心線偏移與路程、輸入/頭部追蹤狀態。
- `frames.csv`：每個 Unity frame 的 CPU frame interval。它不等於 HMD 實際呈現率、reprojection 比例、motion-to-photon 或串流延遲；另用 SteamVR/VBS 的效能工具觀察。
- `events.csv`：開始、暫停、重設、校正、視覺條件、設定快照、不適評分及正常結束。非正常關閉可能丟失最後約一秒的緩衝紀錄。

中心線偏移是相對整條雙向道路的中心，並非右側車道追蹤誤差；右側目標為 +1.75 m 時需另扣除此目標。這一版尚無 hazard onset、TTC、brake RT 或觸覺事件，不會產生假的研究指標。

Editor 僅保留場景開啟、啟動模式與設定檔管理；開發用檢查已移至 `Tools/` 命令列，不需要在 Editor 執行測試選單。檢查在忽略的獨立副本進行，不注入作業系統按鍵。

實機仍需驗收：左右眼顯示、各控制鍵、頭盔移除/斷線停止、眼位重校、鏡面左右方向、串流掉幀與實際不適。桌面檢查無法取代這些項目。

## 可借用的研究思路與適用界線

- [Michel, Espié & Bouaziz, SIMULTECH 2021](https://www.scitepress.org/PublishedPapers/2021/105767/)：提出軟硬體與感覺回饋應相互匹配的假說。借用其模組分工及重視時序的思路；論文本身是 proof of concept，不能說已證明簡化模型能減少暈眩。
- [CTU MotoSim, Sensors 2025](https://www.mdpi.com/1424-8220/25/13/4237)：系統整合實車操作件、轉向、姿態感測與 motion platform，並做實車比較。借用「分項校正操作、以客觀軌跡和主觀感受共同檢驗」的方向；不把缺乏平台的本系統宣稱為等效。
- [Mittelstaedt et al., Displays 2018](https://www.sciencedirect.com/science/article/pii/S0141938217301841)：其自行車情境中，HMD 與螢幕有暈眩差異，腳踏車與 gamepad 控制未見差異。這提醒我們控制件更像真車，不代表一定更舒適；其結果也不是速克達的保證。
- [Scientific Reports 2024 的 VR 機車暴露與休息研究](https://www.nature.com/articles/s41598-024-71526-9)：使用被動騎行視覺刺激與頭部追蹤。借用記錄暴露順序、恢復與休息時間的做法；不以此推論主動轉向控制的效果。
- [Meta locomotion guidance](https://developers.meta.com/vr/design/locomotion-best-practices/)：作為穩定畫面、可調舒適選項的實務參照。騎行所需的連續轉向與加減速仍須在本場景測試。
